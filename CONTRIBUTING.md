# Contributing Guidelines

## Branch Naming Convention

All branches must follow this naming pattern:

- feature/<description> - New functionality
- fix/<description> - Bug fixes
- doc/<description> - Documentation changes
- refactor/<description> - Code restructuring
- test/<description> - Test additions or modifications

Examples:
- feature/add-data-loader
- fix/null-pointer-error
- doc/update-readme

Use lowercase with hyphens for multi-word descriptions.

## Pull Request Workflow

1. Create branch from main using naming convention
2. Make changes and commit regularly
3. Push branch to origin
4. Open pull request to main
5. Request review from at least one team member
6. Address review feedback
7. Squash merge after approval

## Commit Messages

Write clear, descriptive commit messages in present tense.
